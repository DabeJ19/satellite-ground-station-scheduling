### §5.1 新證明：正確

令 n=|R|≥1、H 為正整數、k≤n 為結構合法的已排不同需求數。計分前排除未知引用、重複需求、負／非整數 start；合法需求有 `request.start≤H−1`，故每筆 `wait≥−(H−1)`。即使時窗不可行，仍有：

```text
W ≥ −k(H−1) ≥ −n(H−1)
F = k − W/(nH+1) ≤ n + n(H−1)/(nH+1)
λ = n+1，V ≥ 1
fitness = F − λV
        ≤ n + n(H−1)/(nH+1) − (n+1)
        = −(n+1)/(nH+1) < 0.
```

因此不可行者低於空解 0；可行非空解的等待非負且受 nH 約束，其 F>0，故預設值也保證可行優先。n=0 已由 §1.1 指定直接回空解。證明只適用 λ=n+1（或更大的非負 λ）；規格已說明調低後不再保證。前輪反例 n=1、H=10、需求 start=9、基因 start=0，得 W=−9、F=20/11、V=1、fitness=−2/11，正好等於新上界，與 draft 3 一致。

§5.1 第一段修復說明保留成對衝突敘述，但後段已明確要求完整 checkFeasible，兩者合讀包含單筆頻段／時窗違規，沒有只修復資源衝突的規格缺口。

### §8.4 的 (5,14)：獨立核對成立

把 R1.durMin 改為 7，R1 最晚起始是 3；R2 最早起始 3、最晚 6。若 R2 先做，最早 end=5>R1 最晚 3；若 R1 先做，最早 end=7>R2 最晚 6，故兩者不能共存。既有 R2/R4 互斥仍成立，六任務不可能全排。

可行五任務如下：

| 需求／天線 | 通訊 | 等待 |
|---|---|---:|
| R1 / GS_2-S | [3,10) | 3 |
| R3 / GS_1-S | [6,11) | 0 |
| R4 / GS_2-X | [11,13) | 3 |
| R6 / GS_2-X | [23,25) | 3 |
| R5 / GS_1-S | [25,30) | 5 |

GS_2-X 的 R4 校準到 23，R6 恰在 23 接續；GS_1-S 的 R3 校準到 21，R5 於 25 開始；SAT_B 在 11、SAT_C 在 25 半開銜接。各時窗均容納，Z=5、W=14。

下界亦成立：五任務必含三筆 S，故含 R1、排除 R2，X 選 R4/R6。R6 最晚 24 起始，要求 R4≤12；同 SAT_B 的 R3 必排在 R4 前，否則最早 10 開始已晚於 R3 最晚 9。若 R3 用 GS_2-S，最早 end=13，與 R4≤12 矛盾，故 R3 用 GS_1-S 且 start≥6，推得 R4≥11。R1 若也用 GS_1-S，其最早通訊末端加校準=17，無法與必須在 7 或以前開始的 R3 共存，反向亦不可能，故 R1 用 GS_2-S、start=3。於是 R6≥23；R5 不能先於 R6（R5 最早 end=25>R6 最晚 start=24），故 R5≥25。總等待至少 3+0+3+3+5=14，所列方案達下界。
