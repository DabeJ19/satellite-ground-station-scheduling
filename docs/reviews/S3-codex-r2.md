## 阻擋項（必修）

### N1 — 求解結果替換選中槽，未重新同步播放游標（B2 延伸）

對應：**SPEC §6「播放資料來源／同一游標」、§8 S3**。位置：`src/ui.js` 的 `setSlot()`、`solveMILP()`、`finishGA()`；目前只在切槽事件與 commit 呼叫 `syncPlay()`。

可重現輸入／步驟：

1. 用預設資料將 H 改80，建立其 GA 解槽，選中 GA，`setTime(70)`：滑桿87.5%。
2. 提交預設 H40 資料。舊 GA 槽保留，所以此時 t70 仍合法，而且 commit 確實已暫停。
3. 重新執行一次 GA（例如 `runs=1,popSize=2,elite=1,generations=1,stagnation=1`），讓 `finishGA()` 寫入目前版本的 H40 解。

實測：新 GA 槽 revision 等於目前 revision、`viewNorm().H=40`，但 **t 仍70、滑桿仍87.5%、標籤11:10、動畫 t=70**；甘特圖的時間游標因超界消失。若使用者在等待求解時重新播放，後續 frame 可能重設時間，但暫停狀態會一直保留錯誤。

MILP 也已走實際 UI 路徑重現：保留 H80 的選中 MILP 槽、t70；提交 H40 且 `requests=[]` 的合法資料，再 `solveMILP()`。零候選回傳已證明空解並替換槽後，同樣 H40／t70／滑桿87.5%。因此不是只對測試 API 直接寫槽才發生。

可直接採用的修改文字：

> 解槽寫入也可能更換播放資料來源。`setSlot(name,slot)` 寫入後，若該 name 為目前選中槽，須先依新 `viewNorm()` 呼叫 `syncPlay()`，再儲存／重繪。MILP、GA、手動槽一律走此共同程序；不得只在切槽或 commit 同步。暫停狀態保持暫停。更新未選中的槽不應改動正在檢視槽的時間。

直接補測（輸入＋預期）：

- 上述 GA 與零候選 MILP 路徑完成後，**t=40、滑桿100%、標籤10:40、動畫t40**，甘特圖游標在右端；playing仍false。
- t20／舊H80 時滑桿25%；替換成H40後 t仍20，滑桿必為50%，以免只補超界 clamp 而漏掉一般同步。
- 若僅 timeOrigin 從10:00改20:00，同樣以新槽更新標籤；更新未選中槽時，選中槽的 t／H／標籤不變。

## 建議項（可延後）

### A1 — 補齊時窗編輯器的重繪欄位與無效 H 處理（S4）

對應：**SPEC §6 資料編輯、§8 S4**。這是上輪 A1 的剩餘範圍。有效 H 改動與 id 等主要欄位已落實；但 `onDraftInput` 的重繪 regex 沒有 band／color。實測修改 `requests[0].band` 及 `satellites[0].color`，重繪次數都是0；band 明確出現在列標籤，color 影響時窗顏色。H 清空時 draft H=`''`，編輯器卻用 H=1 繪製，pointer handler 仍啟用。

可直接採用的修改文字：

> 影響時間軸標籤或顏色的 band／color 也觸發 canvas 重繪，不重建輸入表格。H 不是正整數時顯示提示並停用拖曳；有效後才恢復，不用虛構 H=1 接受座標修改。

補測：變更 band／color 後立即觀察列文字／色彩更新且焦點保留；H 清空、0或小數時 pointerdown／move 不改 draft 時窗；恢復H80後可正常拖端點。可於 **S4 編輯器收尾**處理，不新增阻擋。

### A2 — 最小間距仍需處理大量衛星（S4）

對應：**SPEC §6 軌道呈現、§8 S4**。這是上輪 A2 的剩餘範圍。600×400、20星已得到外圈176，含24px留白恰為200，原反例已修正。但最小間距3與地球半徑12仍有容量上限：60星外圈192、加留白216；100星外圈312，超過畫布半高200。現有14星測例未觸及這個分支。

可直接採用的修改文字：

> 衛星數超出固定畫布可容納量時，動態放大可捲動畫布或提供縮放；維持軌道半徑遞增，不以最小 gap 把衛星畫出可視範圍。版面容量應由尺寸／數量計算，而非只依單一14星案例保證。

補測：600×400、60／100星及窄畫布，驗證全部軌道可透過畫布／縮放看到、外圈符號與標籤有空間；既有3／14／20星布局不退化。可於 **S4 響應式／離線驗收**處理，不新增阻擋。
